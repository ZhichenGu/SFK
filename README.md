# SFK 教学工作台

只处理学生上课签单：填写、发链接、学生签名、管理页自动更新、下载与删除。课程类型默认“项目课”，也可选“基础/软件课”。当前按用户要求采用公开共享工作台：无需登录，所有访问者可查看、创建、修改、删除全部签单。

## 第一次配置 Supabase

`config.js` 已填写本项目的 Project URL 与 Publishable key。Project ID 为 `gsbktszybeqhpyirvcaw`，URL 为 `https://gsbktszybeqhpyirvcaw.supabase.co`。公开密钥适合放在前端；不要换成 service_role / secret key。

1. 打开 [Supabase 项目](https://supabase.com/dashboard/project/gsbktszybeqhpyirvcaw)。进入 **SQL Editor → New query**，复制同目录 `supabase.sql` 的完整内容，执行一次。脚本创建表、权限与签名接口；重复执行不会删除记录。
2. **不需要创建老师账号或配置 Authentication。** 如果此前执行过带登录要求的旧脚本，重新执行当前 `supabase.sql`，它会将读取与管理接口改为公开共享权限，保留已有记录。
3. 上传或提交本目录所有网站文件到 GitHub，而不仅是 `index.html`。GitHub 仓库 **Settings → Pages** 选择 `main` 分支根目录。若部署地址不同，修改 `config.js` 的 `siteUrl`。当前预设为 `https://zhichengu.github.io/SFKTeachingWorkspace/`。
4. 直接打开网站，新建一份测试签单，生成链接；在另一浏览器或手机打开链接签名。管理页面可见时约 15 秒内更新，也可点击“刷新签名状态”。

**基础签单不需要 Storage bucket 或 Edge Function，也不需要在前端放数据库密码。** OCR 识别需要单独部署下文的 Edge Function。建表脚本未执行前，不能将学生签名自动同步视为已启用。

## 使用

- 点击左上角品牌区可返回首页；已选择教师时保留当前教师，编辑中的签单先完成保存。学生签名链接中的品牌入口返回网站起始页，未提交签名仍由离页提示保护。
- 左上角当前版本为 `v0.5`（反馈保留可编辑小标题）。版本号是发布标记，不会因刷新或数据库内容变化自行递增。发布前同步更新 `index.html` 的 `app-version` 文字、说明及所有外部脚本的 `?v=` 参数，避免新页面复用旧脚本；切换页面不会改变版本。线上显示取决于实际发布的文件，只有本地修改不会更新线上版本。
- 右上角教师姓名左侧的「签单教程」按钮打开独立教程页，包含「新建签单」「批量新建」三步说明和对应操作入口；首页不再展示教程卡片。筛选栏显示日期起止标签，手机上教程页自动改为单列；页头预览入口只在签单编辑或学生签名页面显示。

### 教师身份选择

- 每次打开网站先进入「选择使用身份」页：列出已创建的教师、`＋ Add User` 新增、`访客模式`。
- 选择教师后进入个人工作台：**只显示该教师自己的签单**（按 `teacher_id` 隔离，不靠姓名）。
- 右上角常显当前教师姓名，点击可「切换用户」回选择页；最近使用的教师记录在 `localStorage`、并置顶。
- 选中教师后，新建/批量/OCR 签单的「导师姓名」默认填入当前教师，教师签名默认用其姓名生成手写体；仍可手动改。访客模式保持自由填写。
- 这是轻量身份层，**没有账号/密码/权限系统**；教师名单存 Supabase `teachers` 表（共享），新增教师用校验 RPC。

### 课表识别新建（OCR）

第三个新建入口。上传课表截图（JPG/JPEG/PNG，点击或拖拽）→ 调 Supabase Edge Function 转 Google Cloud Vision（`DOCUMENT_TEXT_DETECTION`）→ 前端按文字位置解析成课程行 → 人工确认/修改/增删 → 填写内容（可「应用到全部」）→ 批量生成签单链接（复用现有保存与链接逻辑）。

上传区下方提供三步图片教程，使用课程参考图和标明「演示」的核对界面截图，点击图片可放大。图片位于 `assets/ocr-guide/`，随静态网站文件一并发布。

- OCR 结果必须人工确认，不确定的字段留空，不自动编造；学生姓名未确认前不允许生成。
- 卡片式课表按学生姓名标签与词框位置合并：上下排列的起止时间、课程标题和英文全名属于同一节课；教室标签、授课标记和单独时间不会各生成一节课。同名学生不同课时保留为不同课程。
- 确认页保留「原课程」文字，签单课程类型仍使用已有的「项目课 / 基础/软件课」选项；混合标题默认项目课，可手动改类型。未提供完整日期时保留为空，不推测年份或自动填今天。
- 同一页面会暂存最近一张图片的 OCR 结果；返回上传后再次识别同一图片会直接复用，不再请求 Google。刷新页面或换新图片不保证复用；不会自动重复付费调用来修正解析。
- 课表含多个教师时，默认「仅显示我的课程」（按 `currentUser.name` 匹配），可切换「显示全部」。
- 批量生成支持部分失败：显示成功/失败条数，可「仅重试失败项」，不重复创建已成功的签单。

#### Google Cloud Vision 配置（后端）

前端不持有 Google 凭证；凭证放在 Supabase Secrets，仅 Edge Function 使用。

1. [Google Cloud Console](https://console.cloud.google.com) 新建/选择项目，启用 **Cloud Vision API**。
2. 创建 API Key（APIs & Services → Credentials → Create credentials → API key）。
3. 在 Supabase 项目把 Key 存为 Secret：`supabase secrets set GOOGLE_VISION_API_KEY=你的key --project-ref <ref>`。
4. 部署 Edge Function：`supabase functions deploy ocr-schedule --project-ref <ref>`。
5. 验证：上传一张课表截图点「开始识别」，能进入识别结果即成功；缺 Key 会提示「OCR 尚未配置」。

> 未配置 Secret 前，其余功能（身份选择、上传 UI、解析、确认、批量生成）均已可用，仅真实 OCR 调用会被阻断。

## 批量填写（一次一批）

管理页点「批量新建」：顶部设本批次的默认课程类型、日期、时间和导师签名；下面一行一名学生，默认只显示高频字段（学生、上课内容、课后作业），课程类型、日期、时间、第几次课、作业完成收在行内「更多」里，留空即继承批次默认，避免与顶部默认值重复。桌面是表格，手机变成逐份卡片，可「上一份 / 下一份」切换，底部固定「批量保存并生成链接」。

- 新增行继承默认值；个别行不同时在「更多」里单独改课程/日期/时间。
- 上课内容、课后作业在单元格里以单行摘要显示，聚焦时展开编辑，避免长文本撑坏列表。
- 行内操作：「沿用上次」按姓名取该学生最近一份签单、第几次课自动 +1；「复制上一行」复用上一行字段；「更多」展开课程/日期/时间/课次/作业完成；「删除」移除该行。
- 学生姓名框带历史联想（来自已保存记录）。
- 「批量保存并生成链接」：逐份保存并生成签名链接，每份带「复制链接」按钮与「已复制」标记，可一键复制全部链接文本。学生姓名必填，其余空项不拦截。单行失败单独列出，不影响其他行；保存失败的行不会出现链接。
- 草稿自动保存在当前设备、当前浏览器，不跨设备同步。批量生成会保存记录 ID、版本和每行进度；部分失败保留整批恢复信息，刷新后可继续，成功行不重复保存。全部行完成后才清空草稿。
- 保存响应丢失时，重试先查询同一记录的实际状态；版本冲突保留草稿并提示核对，不覆盖重试。浏览器无法保存草稿时会提示，并阻止开始批量写入。
- 导师签名与课程类型作为「常用默认值」持久化：新建单签与批量都会自动带入，保存后回写。

## 自动保存与常用默认值

- 单签编辑器：新建（尚未签名、未发链接）时输入停顿 2 秒自动保存；状态栏明确显示「未保存 / 保存中… / 已保存 / 保存失败」，只有服务器确认成功才显示「已保存」。已签名或已发链接的记录仍手动保存，避免误改自动清空学生签名或使链接失效。
- 导师签名、课程类型存为常用默认值，下次新建自动带入。
- 电脑与手机同时打开同一记录时沿用现有 revision 检查，冲突提示、不静默覆盖。
- 自动保存与手动保存共用同一条保存流程；等待保存时可继续输入，后来输入保持未保存状态。切换教师或返回管理页会先等待保存；失败时留在原编辑器。迟到的记录加载和轮询结果不会覆盖当前编辑。
- 学生提交后回读服务端实际签名，再显示提交完成；提交或回读结果不确定时，再次操作先查询状态，避免把另一端未被接受的签名显示成已保存。

## 本地回归测试

`tests/regression.cjs` 使用真实无头 Chrome 操作页面，Supabase 和 OCR 接口由隔离假数据拦截，并阻断所有非本地请求。它不连接真实数据库、不调用 Google Vision，也不证明线上 SQL 已部署。

环境需要 Node.js、可解析的 `playwright` 包与 Chrome。已有 Playwright 时直接运行 `node tests/regression.cjs`；包在其他位置时设置 `NODE_PATH` 指向对应的 `node_modules`。默认使用 macOS 的 Google Chrome，其他安装位置通过 `CHROME_PATH` 指定。例如：

```sh
NODE_PATH=/path/to/node_modules CHROME_PATH=/path/to/chrome node tests/regression.cjs
```

测试自行启动仅监听 `127.0.0.1` 的临时服务，并在结束时关闭服务和浏览器。覆盖保存与导航并发、轮询晚到、批量恢复与版本冲突、存储失败、OCR 重试和签名回读；不需要为项目添加构建工具或后端。

课程卡片分组另有不依赖浏览器的测试：`node tests/ocr-parser.cjs`。它使用按示例排布构造的词框，验证单卡、上下多卡、并排卡、英文姓名、起止时间和空字段；不调用真实 OCR，不能证明 Google 对任意截图都能准确读字。

## 字体与导出版式

- 填写界面继续用系统字体，加载快、输入自然。
- 预览、文字测量与导出使用**随站点发布的自托管字体** `SFK Serif SC`（Noto Serif CJK SC 的子集，SIL OFL 许可，许可见 `fonts/OFL.txt`），不依赖设备是否安装 Kaiti/Songti。字体加载完成后才重绘预览，导出前等待 `document.fonts.ready`。
- 姓名文字签名在保存时转成小图片固化，跨设备查看不再重新排字，与画笔/上传签名一致。
- 字体未覆盖到的生僻字回退到系统字体，由自动换行兜底，不静默截断。

## 空间与清晰度

云端保存课程文字与两份轻量签名，**不保存整张 A4 图片**。输入姓名只保存少量文字；画笔签名转为小图；上传的签名图片缩放、压缩为每张最多 16 KB。优先保留 PNG，无损压缩不足时使用白底 JPEG。上传签名建议先裁去多余背景。

数据库中的 Base64 编码比原图片字节数约增加三分之一，另有 JSON、行、索引开销。因此“16 KB”是单张签名的图片字节上限，并非整条数据库记录大小。两张图片上限约 32 KB，Base64 约 43 KB，再加文字与数据库开销；文本签名通常远小于这个值。

下载时浏览器生成 1588 × 2246 的 A4 PNG，清晰度优先，文件通常超过十几 KB，但不占用 Supabase 图片存储。将整张 A4 强制压到十几 KB 会明显影响中文与签名辨认，因此没有这样处理。

[Supabase 官方数据库容量说明](https://supabase.com/docs/guides/platform/database-size)：免费计划当前数据库配额为 500 MB，已有系统表等也会占用空间；不能把全部额度当成签单可用容量。轮询只获取轻量列表元数据，不每次读取签名图片；详情或下载时才读取整条记录。

## 课程反馈与 DeepSeek 接入

首页搜索学生后勾选同一学生的1–20份签单，点「一键生成反馈」。填写导师、0–100 的进度、他／她／学生、项目、课堂观察和学习建议。导师一致时带入；作业只取最近一次课程并可修改，最新为空不沿用旧作业，日期缺失时手动填写。混选不同姓名、姓名为空或任一记录读取失败时不生成；姓名并非唯一身份，同名情况需老师核对。

「AI 生成反馈」通过 `cloud.js` 调用 `generate-feedback` Edge Function，再调用 DeepSeek Chat Completions。只发送学生姓名、课程类型、课堂内容及补充字段，不传签名图片、链接、记录ID或日期时间。写作指引从项目 MD 提炼，不再用单一成稿强制套用结构，内嵌在服务端函数中（规则版本2026-10-18-editable-headings），不会自动读取桌面文件。规则保留 🔸 分项的阅读便利，全部小标题固定保留，缺项在冒号后留空以便编辑，正文与篇幅随材料调整，无时间与寒暄、无虚构表现。建议可给方向、方法或自然鼓励，不固定追加鼓励句，不能伪造表现或承诺结果。AI建议仍需老师核对。

可随时选择「使用本地模板（免费）」。AI失败保留输入，不自动重试、不静默改成模板；生成时按钮禁用防止重复点击。关闭弹窗取消浏览器等待，但服务端可能已处理并计费。草稿仅在内存中，不写回签单、不自动发送。

### Supabase 控制台部署

1. 在当前项目的 Edge Functions → Secrets 保存 `DEEPSEEK_API_KEY`。可选 `DEEPSEEK_MODEL`，默认 `deepseek-flash`，另支持 `deepseek-v4-pro`。
2. Edge Functions → Deploy a new function → Via Editor，名称填写 `generate-feedback`。
3. 用 [supabase/functions/generate-feedback/index.ts](supabase/functions/generate-feedback/index.ts) 的完整内容替换编辑器默认代码，点 Deploy function。
4. 该函数沿用工作台免登录模式，JWT验证应关闭（函数设置中的 Verify JWT / Enforce JWT Verification）；CLI部署会读取 `supabase/config.toml` 的 `verify_jwt=false`。
5. 更新网站前端的 `cloud.js` 和 `feedback.js`，然后刷新页面。仅部署函数不会更新旧网页。

无需执行 SQL 或改数据库结构。CLI部署只运行：`supabase functions deploy generate-feedback --project-ref gsbktszybeqhpyirvcaw`；执行云端部署、推送网站及真实付费调用仍需用户授权。

函数限制最多20份课程、请求80KB、模型输入16000字符、输出1000 token，非思考模式，45秒上游超时。每个函数实例每分钟最多10次有效请求；这是临时实例限流，不是跨实例的全局额度，也不是身份验证。工作台仍公开，新增付费函数同样公开可调用，部署者需了解此费用边界。错误信息不会回传密钥或原始供应商错误。

本地验证：`node tests/feedback-function.cjs` 使用模拟 Deno 与供应商，不产生费用；`tests/regression.cjs` 覆盖前端提交、失败后输入保留、重试与免费模板。真实部署和真实模型效果需另行验证。

## 已修正的流程规则

- 不为调整字段、切换签名方式、清除重签等可逆操作反复确认。
- 不因课次等非关键空项阻止预览或发链接；导出统一提示空项。
- 不把“链接生成”“图片下载”误算成“学生已签名”；状态来自实际签名提交。
- 不把公开静态网页当作能保存签名的服务器；共享持久化只由 Supabase 承担。当前不添加账号、登录或身份校验流程。
- 不轮询整张图片；不在云端保存重复的整页 A4 预览。
- 导出、预览共用渲染器，避免两套模板漂移；批量下载逐份生成，失败单独列出。
- 不因切换手机尺寸清除笔迹；异步上传有版本号，清除后旧上传不能重新出现。
- 删除一次确认；修改已签记录后使旧链接失效；重复提交幂等，不重复创建记录。
- 仅未保存编辑触发离开提示；已保存记录和刚打开的默认表单不反复阻拦。
- 项目目前无需构建、第三方字体、CDN、独立服务器、全套设计系统。
