# SFK 功能开发与排错

用于本仓库的功能实现和行为诊断。遵守根目录 AGENTS.md；本 Skill 不新增外部操作授权或固定阶段批准。

## 按问题定位

| 问题涉及 | 优先检查 |
| --- | --- |
| 字段、签名画布、A4 排版、单份导出 | `index.html`，字体相关再看 `fonts.js` |
| 管理列表、自动保存、记录切换、批量下载 | `workspace.js` |
| 学生链接、记录装载、签名提交 | `sharing.js` |
| HTTP、压缩、记录规范化、RPC 参数 | `cloud.js`，规则不一致再看 `supabase.sql` |
| 批量草稿、默认值、部分失败 | `batch.js` |
| 课表解析、确认、生成 | `ocr.js`，服务端调用再看 `supabase/functions/ocr-schedule/index.ts` |
| 教师选择与列表过滤 | `users.js`、`workspace.js` |
| PNG 或 ZIP 打包 | `exports.js` 与 `renderDocument(record)` |

脚本以普通 script 顺序加载，共享全局状态；改装载顺序、拆文件或新增全局符号前检查调用方。仓库没有 package.json 或构建系统；行为回归脚本为 `tests/regression.cjs`，使用隔离接口和浏览器测试，运行方式见 README 的本地回归测试。按改动选择检查，不为单个修复自动建立构建系统。

## 形成证据并实现

- 从用户的触发操作追到状态、请求和展示结果。区分确定缺陷、需运行验证的风险和产品建议；审阅结论给出代码位置与可复现条件，不把风格偏好列为 bug。
- 异步问题重点核对：操作开始时的记录与版本、等待期间是否切换页面或编辑、返回结果是否仍属于当前目标。保存、轮询、手动操作之间需要协调；网络超时不等于服务端未写入。
- 批量流程区分已保存、已发链接和失败项；重试复用记录身份并先核实不确定结果，保留未完成输入。展示状态应来自实际成功结果。
- 只有任务要求修复时实施相关改动；保持公开工作台与已有数据契约。需要数据迁移时可先完成本地迁移方案，不因此停止不依赖它的实现。
- 选择能验证此次行为的检查，按需读取 [verification.md](references/verification.md)。通过后交付；不要把完整清单变成每次必跑步骤。
